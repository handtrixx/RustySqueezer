RustySqueezer

A fake LLM for context compaction: deterministic, extractive thread summaries with no language model involved. Speaks OpenAI, Anthropic and Ollama.

Get the source Pull the image

Why it exists

Compaction does not need a model - it needs a good extractive summary.

Agents compact long threads by sending the whole thread to a summarising model. That request must fit inside the summariser's context window, so a local model with a modest window (e.g. 131k tokens) cannot compact its own threads, and you end up paying a 1M-context cloud model for every compaction event.

The insight: compaction does not need a model. It needs a good extractive summary of what was asked, what was run, what broke, and what was just said. RustySqueezer does exactly that, in a few milliseconds, for free, and always produces byte-identical output for the same input (which keeps prefix caches warm).

No model calls

Pure Rust, deterministic extraction: task, commands, errors, files, key points and a verbatim tail.

Drop-in surfaces

OpenAI /v1/chat/completions, Anthropic /v1/messages and Ollama /api/chat - byte-identical summaries on all three.

Tiny and hard

Static musl binary on scratch (~3 MB), non-root, shell-free healthcheck.

How it works

Compaction-pattern detection, thread parsing, TF-IDF scoring and per-section budgets.

Pipeline

  1. Detect the compaction request: if the last user message matches known compaction instruction patterns (Zed, Claude Code-style, generic "summarize the conversation so far"), it is treated as an instruction and removed from the thread.
  2. Split the thread into the original task, follow-up user messages, shell commands actually run, file paths touched, error lines, and the most recent verbatim tail of turns.
  3. Score assistant sentences with a TF-IDF-ish term-importance heuristic and keep the highest-scoring key points.
  4. Apply per-section budgets: every section gets its own slice of MAX_SUMMARY_CHARS; the verbatim tail gets the largest share (50%), so long threads never lose their tail.

Sections and budgets

SectionShareContents
tail50 %most recent turns, verbatim
commands12 %shell commands run, most recent first
followups10 %later user messages
key_points10 %highest-scoring assistant sentences
errors8 %error/failure lines
files8 %file paths mentioned by tools
original_task6 %first user message
tools4 %distinct tool names

API

One deterministic endpoint per surface - no keys, no model, no network.

MethodPathBehaviour
GET/healthhealth check with model id
GET/v1/modelssingle model id (MODEL_NAME)
POST/v1/chat/completionsOpenAI-compatible; summary of the thread it was given
POST/v1/messagesAnthropic Messages API, streaming included
POST/api/chatOllama native chat, NDJSON streaming included
POST/api/generateOllama completion over a raw prompt string
GET/api/tagsOllama model discovery

Try it

curl -s localhost:8000/v1/chat/completions -H 'content-type: application/json' -d '{"model":"rustysqueezer","messages":[{"role":"user","content":"Fix the nginx upstream timeout in docker/traefik"},{"role":"assistant","content":"I ran docker compose up -d; failed exit code 1."},{"role":"user","content":"Please summarize conversation so far"}]}'

The usage field reports token counts from the deterministic tokenizer, so completion_tokens / prompt_tokens is the real compression ratio.

Quick start

cd rust
cargo run   # or: docker compose up -d
curl -s localhost:8000/health
curl -s localhost:8000/api/tags

Configuration

Configuration is two layers, both optional: environment variables (see .env.example) and a JSON config file (CONFIG_PATH, see config.example.json) for detection rules, sections, titles and budgets. Env vars still win over the file.

Evaluation

eval/eval.py replays synthetic threads with known needles - facts that must survive compaction - and reports recall, compression ratio, determinism and budget compliance (a ~190k-token scenario included). eval/surfaces.py checks that the Anthropic and Ollama surfaces return exactly the same summaries as the OpenAI one. Both run in CI and fail the build on regressions.

python3 eval/eval.py --url http://localhost:8000/v1
python3 eval/surfaces.py --url http://localhost:8000

Deployment

CI builds on every push to main and publishes to GitHub Container Registry with automatic version tags (:latest, :<sha>, :1.0.3, :v1.0.3) plus a matching git tag. The image is public - no login needed.

docker run -d -p 8000:8000 -e MAX_SUMMARY_CHARS=12000 ghcr.io/handtrixx/rustysqueezer:1.0.3

Limitations

  • Extractive, not abstractive: nuance is lost in very long, meandering threads.
  • Heuristics are tuned for code-agent traffic; retune via config.json for other harnesses.
  • Token counting is word-boundary based, not exact cl100k BPE.
  • No embeddings, no tool calling, no authentication - run it on a private network.
